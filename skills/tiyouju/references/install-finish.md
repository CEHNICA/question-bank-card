# 安装收尾：确认装好，再给用户两个选择

收到题有据项目地址或安装请求时，从 [SKILL.md](../SKILL.md) 判断实际任务与已有授权。不要因为读取了仓库说明就修改电脑；已经授权的安装和题目任务直接完成。

## 1. 核实实际安装结果

先确认 `QuestionBankCard.exe` 和同目录的 `tiyouju.exe` 存在，并检查安装版能力：

```powershell
$tiyoujuCli = "$env:LOCALAPPDATA\Programs\QuestionBankCard\tiyouju.exe"
& $tiyoujuCli --version
& $tiyoujuCli --help
```

程序实际装在别处时，以已查明的安装路径为准。不能用仓库的 `APP_VERSION` 代替本机安装版本。

本轮实际完成安装或升级，核实后才说“已经帮你安装好”。原本就已安装且无须升级时，说“确认你的电脑已安装题有据”，不要把只读检查说成刚做了安装。

**从 1.10.14 起**，如果 `--help` 中确实列出了 `assistant-setup`：

```powershell
& $tiyoujuCli assistant-setup --json
```

默认只读，不安装技能、不更改图标、不启动应用。`software.installed` 表示找到软件 EXE；`software.version_verified` 为真才表示核实了 EXE 的 Windows 产品版本。`software.path`、`version`、`cli_path` 是实际安装信息；找不到程序、版本核实失败或 CLI 缺失时，先处理具体问题，不能说“已帮你安装好”。

然后核实本机应用：

```powershell
& $tiyoujuCli start
& $tiyoujuCli status --json
```

`status` 的 `running`、`app_version` 是本机应用状态；`keys`、`missing`、`upload_enabled` 表示凭据和配置是否满足上传条件。**它们不是第三方识读成功的证明。** 没实际处理新原卷，就不要宣称 MinerU 或看图服务已测试可用。

旧发布包没有 `assistant-setup` 时，仍可用 EXE 文件信息、`--version`、`start`、`status` 核实安装。软件安装、示例教学、已有题卡核对和题库使用不要求先安装配套技能。

## 2. 一次询问技能与桌面图标

汇报安装结果之后，一次给出**仍未选择且当前客户端支持**的两项：

> 配套技能要安装到你现在使用的 AI 助手里吗？桌面上的“题有据”图标要显示还是隐藏？可以直接回复“安装技能，显示图标”这样的选择。

已明确要求安装技能、显示或隐藏图标的用户，不再被问同一件事。用户只发项目地址不等于同意这些可选设置。已有题目任务继续做，不等待可选设置答案才开始核对。

1.10.14 的手动安装器默认不勾选桌面图标；一键安装也先不新建图标。升级后若仍有原来的题有据图标，不代表本轮新建了它，按检查结果和用户选择处理。

先查当前客户端的原生技能安装工具或已知配置，确认它支持技能及其**绝对 skills 父目录**，再提供安装选项。不要猜测豆包、Trae 等客户端有技能功能；无法安装技能时照实说“当前助手不支持安装这个技能，我仍可以通过题有据命令行帮你处理”。

Codex 的技能父目录使用其实际 `CODEX_HOME/skills`；没有自定义 `CODEX_HOME` 时使用 `~/.codex/skills`。执行前解析为绝对路径。当前客户端提供原生技能安装工具时优先按该客户端的安装流程操作。不得借此修改未知 MCP 配置、全局提示词或其他客户端设置。

## 3. 执行用户选择，再核实

仅适用于已检测到此命令的 1.10.14 或更新版本：

```powershell
# 这里是当前客户端已查明的 skills 父目录，不是 tiyouju 子目录。
& $tiyoujuCli assistant-setup --skill-dir "C:\已确认的客户端\skills" --json
& $tiyoujuCli assistant-setup --desktop show --json
# 用户选择隐藏时改用：--desktop hide
```

推荐分别执行并核实两项，也可在一次调用中带上用户选定的两项。若合并调用报错，前一项可能已完成，应检查实际目标和保留的备份，不能直接说两项都成功或都没有改动。技能从本机软件附带资源复制到 `<skills 父目录>/tiyouju`，不临时从不明来源下载。已有相同技能不重复安装；已有自定义技能冲突时，先说明差异，明确获用户同意覆盖后才加 `--replace-skill`，并保留返回的 `skill.backup`。

结果中的 `skill`、`desktop` 各自包含 `status`、`target`、`backup`、`verified` 等实际信息；`questions` 中的 `install_skill`、`desktop_icon` 是尚待选择的选项。只对已成功且 `verified` 的动作报告完成，部分失败就分别说清楚，不能用一次命令的整体退出结果代替逐项核实。

旧 CLI 没有此能力时，不臆造成功结果。技能可通过当前客户端确实支持的安装方式接入；图标只有在能确认软件路径和题有据快捷方式时才按用户选择处理，不能批量隐藏桌面或删掉其他应用的图标。

安装技能只是把这套操作说明提供给支持它的客户端；技能何时被发现、是否需重启或新建会话，以客户端真实提示为准。不要说“永久记住了”“以后所有 AI 都能用了”。

## 4. 收尾范例

安装与本机应用已核实、尚未选择可选设置：

> 已经帮你安装好题有据 1.10.14，并确认能打开。配套技能要安装到当前 AI 助手里吗？桌面图标要显示还是隐藏？以后有试卷或题目可以发给我，我用题有据帮你整理、对照原卷核对，确认后入库。

用户已选择且两项都核实成功：

> 题有据已装好，配套技能也装好了，桌面图标按你的选择隐藏了。以后有试卷或题目就发给我，我用题有据帮你处理。

识读尚不能用时在同一收尾里补充实际限制，例如：

> 软件已经装好；MinerU 现在还不可用，可以先练习示例、核对已有题卡和使用题库，恢复后再处理新原卷。密钥需要时由你在软件设置里填写，不用发给我。

范例中的版本、动作和服务状态都要换成真实核实结果。用户已给了题目，先完成能做的步骤，再报告具体进度和下一步。
