# 1.25.95：贴在题上的那颗标签，深底压着深字

老师 10 月 21 日零点发来一张截图，指着「整理勾选题的标签」窗口里「已经在这道题上」的那两颗标签：

> 把字体挡住了，颜色太深

## 一、到底怎么回事

实测（真实程序，1.25.94）：

| | 颜色 |
|---|---|
| 底色 | `rgb(71, 122, 158)` —— 标签自己的深蓝 |
| 字 | `rgb(31, 35, 32)` —— 近黑 |
| 对比度 | **1.83:1**（正常要 4.5:1 以上） |

先说清楚一点：**字和「×」并没有重叠**（量下来差 2 像素）。是**深底压着深字**，看着像被挡住。

## 二、根因：一条早于 1.25.93 的样式

那条样式把标签的颜色**整个当底色**用：

```css
background: var(--tag-color, ...);
```

1.25.93 之前，这颗标签上根本没有颜色（`--tag-color` 没被设上），底色落回浅灰，看着正常。1.25.93 统一给标签上色之后，它就变成了一块深蓝底牌，配上**一直没改过的深色字** —— 两件事撞到一块儿了。

这也是为什么只有这一处不对：题卡上那颗（`.library-card-tag-glimpse`）和题目详情里那颗（`.library-tag-chip`）1.25.93 都改成了「淡底 + 同色边」，唯独批量窗口里这颗漏了。

## 三、这一版改了什么

1. **改成淡底 + 同色边 + 深字**，跟题卡、题目详情那两处一样。

   实测对比度 **7.50:1**（原来 1.83:1）。

2. **补了一条会算账的测试**（`frontend/test_library_tag_contrast.js`）。

   它把样式里的混色比例读出来，按 WCAG 的算法自己算一遍文字和底色的对比度：

   - 淡底要 ≥ 4.5:1；
   - 同时算一遍「拿颜色整个当底色」的老写法，断言它**不合格**（1.83:1）。

   这样以后谁把它改回去，测试会当场变红 —— 不靠眼睛。

3. **顺带扫了全站**：还有没有别的「拿颜色当底色、上面还压着字」的地方。

   三处彩色圆点保留纯色（圆点上面没有字），其余贴标签的地方都是淡底。

## 四、验证

- 前端 `node --test frontend/test_*.js`：**130 项全过**（新增 1 项：标签底色对比度）
- 后端 `manage.py test core`：**2258 项全过**（skipped=6）
- 启动器 `test_launcher test_backup test_app_window test_credential_dialog test_packaging test_assistant_setup`：**131 项全过**
- **4 条变异全部被挡住**：退回「拿颜色整个当底色」/ 混色比例调高到 60% / 不写字色 / 边框不跟标签色。
