# 1.26.51 —— 「AI 识读这题」不再点一下就弹红条：撤回过的题重新能识读了

## 老师报的现象

题卡上的「AI 识读这题」按钮是亮的，点下去却弹一条红褐色提示：

> 这道原图题已有审核、入库或人工文字，已保留；请对照原卷手动修改。

可这道题明明是**原图题** —— 本来就该让 AI 识读它。

## 查出来了：这条提示对这道题是错的

那道题（`question_id=1108`）的真实状态是：

| 状态 | 实际值 |
|---|---|
| 已审核 | 否（`approved=0`） |
| 题干里有人工改过的字 | 否（`edited=0`） |
| 题库里还在用 | **否** |
| 题库里的记录 | **被撤回过** |

挡住它的，是一条**已经被撤回的入库记录**。

### 撤回过的记录，本来就不该挡

老师从题库里「撤回」一道题，意思正是「**这道我不入库了，我要回原卷重做**」。
撤回过的记录不在题库里了，它挡不住任何东西 —— 更不该挡住这道题重新识读。

可旧口径是「只要有过入库记录就算」，于是撤回过的记录照样挡住识读。

### 本机真库实测：392 道题是这样被挡住的

在老师的真库上查了一遍（只读，没动一个字）：

- 旧口径下会被挡住的原图题共 **434 道**；
- 其中**正好 392 道**只因为「有过入库记录（已撤回）」被挡 ——
  不是审核，不是人工文字；
- 这 392 道题的入库记录**全都撤回了**，题库里**一条活的都没有**
  （在用的入库记录计数为 **0**）；
- 入库时保存的题面与当前题目**逐字相同**（397 条里 **394 条完全一致**）——
  也就是说那些记录里**根本没有人工成果**。

另外查清了撤回是怎么来的：这批记录的 `withdrawn_at` **395 条共用同一个微秒级时间戳**，
且发生在同一次「按已授权章节结构替换」的换题批次前 26 毫秒 ——
**旧分段留下的入库记录，随旧分段一起作废**。这正是「换题后旧入库作废」的预期语义。

### 新旧口径对比（本机真库实测）

| 口径 | 被挡住的原图题 |
|---|---|
| 旧（有过入库记录就算） | **434 道** |
| 新（只有还在用的才算） | **42 道** |

这一版放行 **392 道**。

## 改了什么

### 只有还在用的入库记录才挡

```python
# 旧：撤回的、被替代的也算
if question.publications.exists():
    return PUBLISHED

# 新：只认还在题库里的那些
if question.publications.filter(status=PublishedQuestion.Status.PUBLISHED).exists():
    return PUBLISHED
```

### 真正的保护一条没少

| 情况 | 还挡吗 | 为什么 |
|---|---|---|
| 已审核通过 | **挡** | 要重新识读请先撤销通过 |
| 题干里有人工或助手改过的字 | **挡** | AI 会盖掉它，要改请用「改字」 |
| 还在题库里的 | **挡** | 要改请到题库里改 |
| 入库记录已撤回 / 被新版替代 | 不挡 | 不在题库里了，挡不住任何东西 |

### 判据只有一处

识读接口的拒绝、落库保护、页面判灰，读的都是同一个 `backend/core/cut_guard.py`。
不会出现「页面放行、接口才拒绝」这种事。

### 上一版补的「按钮该灰没灰」，这一版也在

被真正保护的题，「AI 识读这题」在**点之前就灰掉**，并且说清是哪一条挡着、
下一步去哪：按钮本身 + 悬停说明 + 旁边那行常驻小字。

这一版把该灰的灰住，更把**不该灰的放行**。

## 安全

- 题库里的东西一个字没改：题干、答案、解析、图片、标签、搜索索引原样。
- 真库全程只读，没动一个字。
- 不调用识读服务、**不花额度** —— 要不要识读还是老师自己点。
- 撤回过的题重新识读出来的是**新内容**，题库里那一条记录仍然是撤回状态，
  两者不冲突。

  每一条都是「把这个功能弄坏，看测试能不能抓住」。
