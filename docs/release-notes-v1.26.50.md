# 1.26.50 —— 软件打开快了：先亮出来，数据在后面慢慢跟上

## 老师提的原话

> 你先打开再说嘛，其余的加载你慢慢的加载，先打开呀。

这句话说的是**打开速度**。这一版就照这个改。

## 改了什么

### 窗口先出来，列表在后面慢慢加载

以前软件在开窗之前，会先把整份试卷列表先算一遍。那一遍要 **13 秒**
（几千道题的文本第一次解析，光解析就占 3.3 秒），
老师只能对着启动画面干等。

现在：**服务一就绪就开窗**，列表在窗口里加载。

### 列表没到位时，那一栏说清楚在做什么

左边「试卷」那一栏在等待时不再是空白，写着「**正在准备试卷列表…**」。

- 提示就写在那一栏里 —— 老师看的地方，不弹到屏幕中间挡视线。
- 列表一出来，这句话自动收走。
- 热启动（列表马上就到）不闪一下。
- 等超过一分钟，会改成「**试卷列表还没准备好，程序会自己再试一次**」——
  说明白程序没死、还在试。

### 第二次打开明显快了

每道题要算一次「判定」：能不能通过、配图有没有挡住、题库里是不是已经是这一版。

这个判定结果**现在存到磁盘上复用**。理由是站得住的：

- 判定依据的是题目本身。题目一个字没改，判定结果就一定是同一个。
- 判定里带着「指纹」——题目全部内容、题组、卷名、题库里的版本号一起算出来的。
  指纹一样，判定必然一样；指纹一变（题目改了），立刻重算，绝不拿旧结论糊弄。

存下来的**只有「题目编号 + 指纹 + 判定」**，没有题干、没有答案、没有图片。

### 顺带删掉后台抢跑的那一遍

后台原来会自己先跑一遍试卷列表，等于跟老师自己的请求各算一遍 ——
两边抢同一台机器的 CPU，反而更慢。改成**谁请求谁算，算完存下来**。

## 安全

| 情况 | 怎么办 |
|---|---|
| 缓存文件坏了 | 当作没有缓存，重新算一遍，软件照常打开 |
| 判定规则改了 | 整份缓存作废，重新算一遍 |
| 题库大变了 | 缓存太大就丢掉重来 |
| 多个进程同时想写 | 只有开网页服务那一个进程会写，别的不碰 |

## 验收

- 这一版的「改坏了就废」检查一共 **15 条，全部被挡住**。
  每一条都是「把这个功能弄坏，看测试能不能抓住」。
- 后端 **2525** 项、前端 **160** 项、桌面外壳 **147** 项，全过。

## 这次没动的

题干、答案、解析、图片、标签、搜索索引原样，不调用识读服务、不花额度。
