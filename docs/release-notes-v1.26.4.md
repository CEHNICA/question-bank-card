# 1.26.4：真合并报错了 —— 外键断了

1.26.3 撤掉了页面自绘的窗口按钮。同一轮里还修了另一个更要紧的问题：**把一台电脑的备份
合并到另一台电脑上时，真合并报"FOREIGN KEY constraint failed"**（预览是好的，看不出
问题）。

## 怎么回事

题目不光是"一张卡"，它外面还挂着几样东西：

| 挂在哪 | 是什么 | 不跟着走会怎样 |
|---|---|---|
| `core_question.group_id` | 题组（一、二、三 大题这些"题号作用域"） | 题指向不存在的题组 |
| `core_question.deletion_batch_id` | 删除批次（一次"删掉这几道题"的动作） | 题指向不存在的批次 |
| `core_librarytagassignment` | 题上贴的标签（指着入库快照和标签） | 挂接指向不存在的快照 |
| `core_librarytag_groups` | 标签属于哪个目录 | 标签丢了目录归属 |

原来的合并只搬卷子、题、快照、解析、标签 —— 上面这几样没搬。搬过来的题就指向了
**不存在的行**。

**为什么预览看不出问题**：预览只读不算，写库时才检查；而且 SQLite 是**提交那一刻**
才查外键 —— 一查就整次退回。老师看到的就是"预览说得好好的，一点合并就失败"。

真机上量到的：这台电脑的 898 道题里，**599 道指向没搬过来的题组、69 道指向没搬过来的
删除批次**，另有 20 条标签挂接断了。

## 改成什么样

- **题组**跟着卷子一起搬，指向改成本机编号；
- **删除批次**跟着搬（批次本身是"一次删除动作"，两台电脑各记各的，另给编号），批次里
  "删掉的是哪几道题"改成本机编号 —— 这样在另一台电脑上删掉的题，这里也能还原；
- **题上贴的标签**、**标签属于哪个目录**都跟着搬；
- 认题组**只按序号**：组名会重复（同一本书里好几个"第 70 组"），按名字认会把一组认成
  另一组，题就落进了错的组里；
- 已经撤回、题目又被删掉的旧快照（没有题可跟）也照搬，不再漏；
- **撤销**也跟着补齐：题组、删除批次、标签挂接、试卷块、框选记录，撤一次干干净净。

## 怎么验的

拿老师那台电脑上真导出的备份包（8 套卷子、829 道题、302 个标签、88MB）在隔离环境里
跑：

- 合并前：外键一查 —— 688 处断链；
- 合并后：**外键 0 违反**；卷子 8、题目 898、题组 167、删除批次 12、入库快照 869、
  标签 302、标签目录 18、标签归属 282、标签挂接 18 —— **和备份包里一一对得上**；
- 撤销一次：全部回到 0 ✓。

另外补了三条自动测试（题组/删除批次/标签挂接跟着走、合并后没有断链、撤销一并带走），
以后再动这几张表会被挡住。
