# 1.26.32：导出失败会说人话，不再只剩一句「请稍后重试」

老师转述的用户反馈：「他 Word 显示『Word 未能导出，请稍后重试』」。

## 一、这句话是什么意思

它不是后台给的结论，是**网页上的兜底话**。后台回了一个「不是成功」、
而且正文又不是带错误说明的 JSON 时，前端只能这么说。查下来，导出这条路上
**已知的失败全都带原因**：

- 配图文件缺失、损坏或过大 → 「第 N 题（哪份原卷第几题）· 配图 1：文件缺失、损坏或过大」
- 本机浏览器排不了版 → 说清是哪一道题排不了
- 选题内容太多 → 「超过 2 MiB，请减少选题、分批导出」
- 这道题已被撤回或被新版替代 → 说清是哪一条

所以那个用户碰到的是**没被接住的意外错**。而这件事的后果被放大了两层：

1. **网页上只说「请稍后重试」。** 要是原因其实是永久性的（比如某道题的配图真没了），
   重试一万次也没用 —— 用户只会一直重试，一直不明白。
2. **日志里连堆栈都没有。** 程序只把「core」这个 logger 接到输出上，
   Django 自己那个「这次请求炸了」的 logger 没人接 —— 8.6 MB 的日志里一条堆栈都没有。
   事后连「到底为什么失败」都查不出来。

## 二、这一版改了什么

- **后台加兜底**：Word 和 PDF 导出撞上意外错时，回一句能转述的话 +
  一个查得到的诊断号（本机诊断号 EX-…），并把堆栈记进日志。
  话是：「Word导出没完成（诊断号 EX-1A2B3C4D5E6F）：你的题和原卷都没动。
  可以再试一次；还是这样就把这个号发给开发者。」
- **日志接上**：给 Django 自己的报错 logger 装把手，堆栈不再哪儿也不去。
- **前端最后那道兜底**：不能再是「请稍后重试」（那只会让人一直重试），
  改成说清「后台没给出原因」，并请用户把出问题的题目和时间告诉开发者。

## 三、真机验过

- **导出本身没坏**：本机真数据真点「导出 Word」，5 道题 2 秒导完，后台回 200，零报错。
  196 张入库配图一张不缺。
- **意外错时**：在导出里临时制造一次意外错，真界面上显示的是
  「Word导出没完成（诊断号 EX-1C238A562897）：你的题和原卷都没动。可以再试一次；
  还是这样就把这个号发给开发者。」日志里同一个号下面就是完整的堆栈。
- 三条改回老样子的变异（删掉后台兜底、不记堆栈、前端改回「请稍后重试」）**全被挡住**。

## 四、给老师的一句话

以后那个用户再遇到导出失败，屏幕上会有一句说清发生了什么的话和一个诊断号。
**让用户把诊断号和「哪道题、什么时候」一起报过来**，凭号就能在日志里查到真正的原因，
不用再猜。
