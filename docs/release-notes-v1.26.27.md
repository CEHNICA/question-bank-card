# 1.26.27：标签不再按类型分家

**老师原话：「知识点标签儿和什么各种各样标签儿之间啊，他没法就好像给强行区分开来了。那我觉得其实没必要，他们都是标签儿而已，你没必要给他区分开。我今天啊我拿两个标签儿，我想给他合并啊，想给他并列来着，结果他给我说什么一个是知识点标签儿，一个是解题方法。」**

## 一、原来拦他的地方，一共三道

| 做什么 | 以前的结果 |
| --- | --- |
| 合并两颗标签 | 「只能合并同类型标签」—— 而且别类的那颗**根本不出现在「保留哪一颗」的下拉里** |
| 把一颗拖到另一颗下面（挂靠） | 「知识点和解题方法是两类，不能相互挂靠。」 |
| 让两颗并列 | 同一句「不能相互挂靠」 |

还有一道在后台（前后端各拦一次）。这一版全拆了。

## 二、现在是什么样

- **合并**：别类的标签也能选。合并后类型跟着「保留的那颗」走。
- **挂靠 / 并列**：拖一颗知识点标签到一颗解题方法标签上，照常弹「两颗标签怎么排？」，
  两个排法都能选。
- **目录和文件夹树里，跨类型的子标签画得出来**，名字后头标出它是哪一类
  （以前按类型过滤，那颗会「消失」—— 挂了却看不见，等于白挂）。

## 三、有一件事会跟着变

**知识点是整题，解题方法可以只对某几小问。**
知识点合成到解题方法上时，那个方法在这道题上会变成**整题**。
合并前的确认框里会写明这一句，不让你事后才发现。

「相关方法」那条关系不变：还是知识点指向解题方法，它不参与上下级。

## 四、怎么验的

- 后端：跨类型的上下级能建成（环还是拦得住）；跨类型合并后类型跟目标走、
  适用范围变整题、撤销能还原。
- 前端：拖放、挂靠、并列三条路都真的发请求（不是弹一句「不能相互挂靠」）；
  合并的下拉里别类的标签也在；目录里跨类型的子标签画得出来。
- 8 条改动逐条弄坏，看测试是不是真拦得住 —— **8 条全被拦住**。
- 三组测试全过：后端 2341 条、前端 137 条、外壳 128 条。
