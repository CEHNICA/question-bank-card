# 1.26.53 —— 助手工作台字符级 Diff、SQLite WAL 并发无锁、CLI 题卡体检与教辅黄金语料集

## 这一版忙了什么

从 1.26.51/52 走过来，题有据的核心能力已经成熟稳定。但在多道大教辅（如《高中数学思想方法导引》509 题）和人机协同审核（老师查题、AI 助手改字改题）场景下，几个深水区痛点被彻底攻克：

1. **老师看题翻页时，AI 助手交活不再报「database is locked」**。
2. **助手工作台改了哪几个字、哪个公式，红绿字符级对照一目了然**。
3. **500 道题的大教辅，CLI 一键体检大盘（`--summary`），1 秒摸清全部卡点**。
4. **备份支持导出到指定 U 盘或备份目录（`--dest`）**。
5. **建立教辅排版黄金语料集（Golden Corpus），防止文本规范清洗倒退**。
6. **核心后端与前端差异引擎模块解耦，零额外打包依赖，秒启秒测**。

## 核心改动详解

### 1. SQLite 开启 WAL 并发模式：读写彻底互不阻塞

#### 痛点
老师在软件界面上一页页翻阅试卷、搜索题库，同时外部 AI 助手（通过 CLI、Cherry Studio 或 MCP 协议）批量分析并提交题面修改或领活。旧的 SQLite DELETE 日志模式下，写入会锁住整个数据库，极易偶发 `database is locked`。

#### 解决
在底层连接初始化钩子中，统一开启 SQLite 的 WAL（Write-Ahead Logging）预写日志机制：
- `PRAGMA journal_mode=WAL;`
- `PRAGMA synchronous=NORMAL;`
- `PRAGMA busy_timeout=5000;`

**实测效果**：
- 读操作与写操作完全并发，老师在前端筛选题库时，外部批量写入提案 0 延迟，彻底告别单机锁库。
- 即使在热读热写过程中，全量 168MB 数据库与原卷截图也能在 1 秒内安全冷备打出。

---

### 2. 助手工作台：字符级红绿 Diff 对比（原生零依赖）

#### 痛点
AI 助手交了改题提案，老师在工作台上只能看到一整段新题干，往往得花眼力逐字比对到底改了哪个数字、漏了哪个负号，还是改动了 LaTeX 公式。

#### 解决
- 独立编写纯原生字符级差异算法模块 `frontend/library-diff.js`（基于经典 LCS 动态规划算法，挂载 `global.TiyoujuDiff`，兼容浏览器与 Node.js 测试环境）。
- 审阅界面实时展示精细的原题与修改后对比：
  - 红色删除线（`<del>`）：展示助手删掉的错别字或旧公式。
  - 绿色高亮框（`<ins>`）：展示助手补充的标准符号与订正。
- **坚守零构建铁律**：不需要 Webpack、Vite 或 Babel，通过原生 DOM API 渲染，杜绝 `dangerouslySetInnerHTML`，安全防注入且秒级启动。

---

### 3. CLI 题卡体检命令：`cards --summary`

#### 痛点
面对包含 500+ 道题的大教辅或全书切片，运行 `tiyouju cards` 会向终端平铺数百道题卡的明细，输出几万行文本，难以掌握整卷的全局健康度。

#### 解决
新增 `--summary` 参数：
```bash
tiyouju cards a34d7cba --summary
```
**实测输出示例**（《高中数学思想方法导引》509 题）：
```text
a34d7cba 高中数学思想方法导引：509 道（筛选：all）
  审核状态：已通过 0（人工 0 / AI 0），待核对 508，就绪绿卡 1，已入库 0
  拦截疑点：题型未定 42 道，配图待确认 508 道，原图题 508 道
  高频疑点：
    - 按章节结构重新提取，请对照新原图范围核对；原审核记录保留在旧版本中。 (508 道)
    - 题型还没定：用 fix --type 选题型后才能通过 (42 道)
    - 文字是本次候选，显示和出卷以原图题面为准 (42 道)
```
- 耗时从原先遍历渲染的数秒缩减至 1 秒以内，疑点分布、题型缺失、待审核占比一目了然。

### 4. 备份支持外部目标路径：`--dest`

支持直接将完整题库备份导出到指定目录或外部移动存储设备：
```bash
tiyouju backup --dest D:\backups\202611
```
- 后端新增目标路径参数校验与写入流，同时保留原有自动轮转备份机制。
- 针对 13 份真题卷、1699 张题卡、1267 张入库题、10833 个 OCR 块（168MB），1 秒内完成快照与原图打包。

### 5. 教辅排版黄金语料集（Golden Corpus 回归网）

#### 痛点
高考真题、省市模考和名校教辅排版千奇百怪：有括号夹带分数或难度的（如“（2025·全国甲卷·理·12分）”）、有栏目名后压题源的（如“（创新考法）（2024·湖北武汉月考）”）、有题干开头包含“满分150分”说明的。以往改动一处规范清洗逻辑，极易引发另一处题源截断失效或锚点误报。

#### 解决
在 `backend/core/test_golden_corpus.py` 中建立真题黄金语料集：
- 严格固化 9 大极端排版形态的题源提取与锚点比对行为。
- 执行耗时仅 0.002 秒，为未来一切排版清洗算法提供不可逾越的护栏。
