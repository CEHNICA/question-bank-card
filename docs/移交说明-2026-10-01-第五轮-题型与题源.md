# 移交说明：第五轮 题型、题源与题库附加信息（2026-10-01）

分支：`improve/1.10.0`，接在 `main`（`32baa6a`，即 v1.9.1 + README 中文关键词）之后。版本号 `1.10.0`（`backend/core/version.py`）。用户可见的说明见 `docs/release-notes-v1.10.0.md`。

起因：用户截图里一道题（[2026山东枣庄滕州二中月考] 集合 + 全称/存在量词命题，两问）在题库里显示“题型待核对”，题库页改不了题型。查下来有三层原因：

1. 题库是不可变快照，改题型的入口只在题卡“改字”里，题库页没有路过去；
2. 题型为 `unknown` 的题不加任何提醒，照样是绿卡，“一键通过绿卡”直接放进题库；
3. 为什么是 `unknown`：读题词表只认“单选/多选/选择/填空/解答”，切题词表还认“计算/证明/简答/应用”，两边不一致；另外**裁决（arbiter）输出格式里没有【题型】**，裁决文字胜出时题型就丢了，退回切题阶段的题型（教辅汇编没有“三、解答题”这类大题标题，切题也是 unknown）。

用户要求“一次做好，一些功能默认不打开”。

## 改了什么

### 题型（不设开关）

- 新模块 `core/qtypes.py`：唯一一份题型表（新增 `true_false` 判断题）和词表 `TYPE_WORDS`，`readers.parse_reading` 和 `segment._section_type` 都用它；读题提示词改为“单选题/多选题/填空题/判断题/解答题”。
- `pipeline.read_card`：最终稿没有题型时取两位读者一致的题型（`qtypes.consensus`）；仍未定时 `qtypes.infer` 只做两条保守推断：有 A–D 选项 → 选择题（题干有“多选/不定项”→多选）；无选项且行首 (1)(2) 连续 → 解答题。`assistant_draft` 也用 `infer`。
- **拦截**：`library.type_blocks_approval()`；`approval_is_current()` 把它算进去（和配图拦截同一个位置），所以 1.10 以前通过的 unknown 题，审批自动失效。单题通过（人工和 `by: ai`）返回 400，`approve-green` 跳过，`library.publish` 抛 `ValueError`。`question_json` 多 `type_blocked`。
- 提醒：`qtypes.FLAG_TYPE_UNKNOWN`；`qtypes.sync(flags, state, kind)` 只在这条提醒增减时改颜色，其他 flag 的颜色逻辑不变。读完写库（`pipeline.read_questions` 的 `persist`）、改字、新的 `type` 动作、启动整理都调用它。
- 新的题卡动作 `POST /api/questions/<id>/type {question_type}`：只改题型、清审批，不动文字、不把题卡标成 `edited`。
- `persist`：人改过（`edited`）且题型已定的题，重读不再覆盖题型（以前会被读题结果覆盖）。

### 题源（开关 `origin_split`，默认开）

- `Question.origin`（迁移 `0014_library_extras_and_origin`）。`textnorm.split_origin()`：只认题干最开头的成对括号 `[] 【】 () （）`，4–60 字、无 `$`/`\`、至少 2 个汉字、有年份（19xx/20xx）或考试词（月考、期中、联考、真题、新课标……），排除“满分/N分”。后面必须还有题干。
- **在哪一步拆**：写库时（`persist`），不是在 `parse_reading` 里。原因：MinerU 旁证（witness）里还带着题源，若在读题阶段就拆掉，`witness_agrees` 会因为多出一段前缀而判不一致，绿卡变少、多花复核调用。写库时拆，识读一致性判断完全不受影响。
- `library.final_content` 带 `origin`；`content_hash` **只在 origin 非空时**纳入，所以老快照、老审批的哈希一字不变（有测试）。
- 题库搜索文本含题源；打印默认不印（“印题源”开关）。
- 改字接口接受 `origin`（`prose.clean_origin` 去掉外层括号、合并空白、限 120 字）；人填的题源优先，自动拆出的只填空着的。

### 中文引号（开关 `chinese_quotes`，默认开）

- `textnorm.chinese_quotes()`：跳过 `$…$`、`$$…$$`、`\(…\)`、`\[…\]` 和 HTML 标签；引号数为奇数或一对引号跨行时整段不动；只有一侧挨着汉字/中文标点或引号里有汉字才换。
- 写库、改字保存、启动整理三条路都走 `core/prose.py`（`tidy_stem / tidy_value / tidy_fields`），结果一致。

### 老数据（启动时整理）

- 沿用 1.5.1 的 `library.tidy_saved_cards()`（`run_worker` 启动时调用）：`tidy_text` 现在返回 `(stem, options, type, origin)`，加上题源拆分、引号；答案、解析也换引号；可读题卡补/去掉题型提醒。审批原本有效的照旧保留（重算哈希），已入库快照就地更新、不出新版本——和改任务名、去“例1”同一套做法。开关关着就不动文字。

### 题库附加信息：知识点、AI 参考答案（开关默认关）

- `PublishedQuestion.extras`（JSON）+ `tags_text`（`|甲|乙|`，按标签整段匹配筛选）。不属于快照、不进哈希；再入库出新版本时 `library.carried_extras` 带过去（标签总带；AI 答案只在题干和选项没变时带）。
- 新模型 `LibraryJob`（tags / answer；queued / running / done / failed）。**网页进程拿不到密钥**（见 test_launcher 的 secrets 测试），所以网页只排队，`run_worker` 主循环在重读之后调用 `library_jobs.process_pending(limit=5)`；启动时把 running 退回 queued。
- `core/knowledge.py`：知识点目录 `DATA_ROOT/knowledge-points.txt`，首次使用写入默认目录（人教A版 2019 必修一、二，选必一至三各节名）。模型只能从目录里选，`match_tags` 按去空白/括号的键精确匹配，最多 3 个。
- `core/library_jobs.py`：提示词、模型回复解析（自己的 `【答案】【解析】【知识点】` 解析器——`readers.TAG` 只认读题用的那几个标签）、失败原因（没有可用读题服务时写明去设置里填密钥）。
- 接口：`POST /api/library/jobs {kind, ids | missing: true}`（开关关着时 409）；`GET /api/library` 新参数 `answer=yes|no`、`tag=`，新 facets `answers`、`tags`，每条多 `origin / has_answer / subquestions / tags / ai_answer / jobs / job_errors`，并返回 `features`。

### 功能开关

- `core/features.py`，文件 `DATA_ROOT/features.json`（可用 `QB_FEATURES_FILE` 覆盖），网页和工作者共用；缺文件/坏文件按默认值。`GET/POST /api/settings/features`。设置页“常用”最下面一节。

### 前端

- `app.js`：题号旁的题型下拉（`typePicker`，未定时琥珀色“题型未定 · 请选”）；`typeBlocksApproval` 接入打勾方框、Enter、放大窗口按钮、`needsCheck`、绿卡计数和筛选；卡片动作行出现主按钮“选题型”；`?document=&draft=&fix=type` 深链；题源一行；改字多“题源”；试卷名像照片文件名时出现“起个好认的名字”；设置里的功能开关。
- `library.js`：“题型待核对 · 去选题型”链接；题源；“无答案”；有/无答案筛选；知识点下拉与标签；“打知识点标签”“AI 解答”按钮与批量按钮；有排队任务时 4 秒轮询；打印“印题源”“附 AI 参考答案”，判断题分组。
- `qb-render.js`：`true_false` 名称；`tidyText` 把 (1)(2)… 前的空行收成一行（只改显示）；导出 `tidyText` 供测试。

### tiyouju（命令行 / MCP）

- `cards/show` 多 `type_blocked`、`origin`；疑点第一条“题型还没定…”。`fix --type` 单独使用时调用新的 `type` 动作（不会像改字那样清掉其他疑点）；`fix --origin`。`library --answer/--tag`，结果带题源、知识点、小问数。MCP `fix_card` 加 `origin`，`search_library` 加 `answer`、`tag`。`skills/tiyouju` 文档已同步。

## 需要注意 / 没做的

- 题型拦截对已入库的老 unknown 题：快照不变（还是“题型待核对”），对应题卡在启动整理后变黄、审批失效。用户点题库里的链接选题型再入库即可。
- 题源只认题干**开头**；印在题尾的“（2023·北京卷）”不拆，避免误伤。
- 中文引号也会作用于人手打的英文引号（保存时）。觉得不合适可以在开关里关掉。
- AI 参考答案用主读题服务（视觉模型）做，数学正确率没有专门评测；界面和打印都标着“未核对”。知识点目录只是默认值，不同学段请自己改文件。
- 后台任务每轮最多做 5 个，在读卷、重读之后做；大量排队时会慢慢做完，不会挡住新卷子。
- 没有做：题尾题源、按小问存储答案、AI 按知识点组卷（为以后“从旧题里挑作业”留了 `tags`、`subquestions` 字段）。
