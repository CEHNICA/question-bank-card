# 移交说明：速度、准确率与审核减负（2026-09-28）

分支：`improve/accuracy-speed-review`（基于 v1.3.0，`2c1a27d`）。本轮用真实 MinerU + MiniMax 账号，在 5 份真实样卷上反复跑“改前 / 改后”对比，每处改动都有对应的单元测试。

## 一句话结论

同样 5 份卷，处理总时长从 **26 分钟降到约 4 分半**（约 6 倍）；高考卷从 5 分 51 秒降到 38 秒。切题从“漏 5 题、多出 6 张废卡、4 份卷要人工确认结构”变为 **112 题全部切对、无废卡、无需确认**。识读上最大的变化是：**不再让同一个模型“自己跟自己比”**，而是用 MinerU 自己识别的文字做独立旁证，既省掉一半复核调用，又能发现模型“帮原卷改字”的错误。

## 实测对比

样卷（仅在本机测试，未进入仓库）：2024 高考甲卷（数字 PDF 5 页）、初三菱形周清（扫描 2 页）、胜利初二月考（扫描 4 页，含学生作答）、口镇高中（扫描 2 页，大量手写）、陈毅初三（4 张手机照片，含作答）。单个 MiniMax 账号、单个 MinerU 账号。

| 高考甲卷 | 351 秒 | 38 秒 | 9.3× |
| 菱形周清 | 267 秒 | 28 秒 | 9.5× |
| 胜利初二 | 316 秒 | 47 秒 | 6.7× |
| 口镇高中 | 252 秒 | 48 秒 | 5.3× |
| 陈毅照片卷 | 372 秒 | 94 秒 | 4.0× |
| **合计** | **1565 秒** | **259 秒** | **6.0×** |

| 指标 | 改前 | 改后 |
| --- | ---: | ---: |
| 模型调用次数 | 266 | 194 |
| 其中复核调用 / 裁决调用 | 113 / 33 | 68 / 10 |
| 单次调用最长耗时 | 17 秒（另一轮 64 秒） | 9.4 秒 |

识读忠实度：对改前改后结果不同的 20 多道题逐一看原卷截图裁定，改后几乎全部与原卷一致。典型的改前错误：循环小数 `0.1212212221…` 被读成 `0.12122122221…` 且是绿卡；原卷印的“蒋铭祖对《蒋铭祖算经》”被模型“纠正”为“赵爽对《周髀算经》”；“相交点 O”被补成“相交于点 O”；汉字“平行四边形”被换成 ▱。

## 做了什么

### 1. 速度

- **账号内并发**（`account_pool.py`）：原来每个账号同一时刻只发 1 个请求。实测单个 MiniMax Token Plan key 同时 8 个请求无任何 429，延迟只从 3.7 秒升到 5 秒。现在每个账号可同时承载多个请求（MiniMax 默认 6、硅基流动 2、MinerU 1），优先分给最空闲的账号；**每遇到一次 429 就永久减掉该账号一个并发名额**（本次运行内），不会越跑越猛。
- **读题并行度**跟随账号容量自动计算（启动器：账号数 × 每账号并发，上限 16）；设置里新增账号后，下一批任务按实时容量提高，不必重启。用户显式设置的 `QB_PARALLEL` 不会被改动。
- **MinerU 旁证代替同模型复读**：见下一节。第二次视觉调用减少约 40%。
- **拖尾请求对冲**（`readers.chat`）：约 1/30 的请求会卡 40–65 秒才返回（只输出一百多个 token），一张卡拖住整份卷。请求 18 秒未返回就再发一份相同请求，谁先回来用谁。温度为 0，两份结果等价，只影响耗时。
- **MinerU**：前一分钟每 2 秒查一次结果（原 5 秒）。
- **重读优先通道**（`run_worker.reread_lane`）：原来在处理一本书时，别的卷“调整范围后重读”要等整本书读完。现在已完成任务的单题重读由后台通道即时处理，不碰正在处理的任务。
- **读题时显示按实测速度估算的剩余时间**（至少完成 4 张卡后才显示）。

### 2. 识读准确率（忠实度）

- **跨引擎旁证**（`textnorm.witness_*`、`pipeline.read_card`）：MinerU 解析时已经为每个文字块给出了自己的 OCR 文字，这是一个与视觉模型完全独立的引擎。
  - 主读结果与该范围内 MinerU 文字**逐字一致**（忽略标点、空格和 LaTeX 写法差异，但保留每个数字、字母、运算符和汉字）→ 直接采用，`text_source = "witness"`，界面显示“两种引擎一致”，不再调用复核模型。
  - 不一致（包括手写答案、看不清 `[?]`）→ 照旧请复核模型再读一遍。
  - 两次读法有分歧时，先把**每一处分歧**连同两侧上下文到 MinerU 文字里查：所有分歧都支持同一种读法才直接采用，否则再请裁决模型，并把 MinerU 文字作为参考一并给裁决模型。分歧在开头或结尾（缺少两侧上下文）时一律交给裁决，防止“漏读第一句”的读法因为“什么都没写”而胜出。
  - 只用 MinerU 的文字/标题块做旁证：学生草稿多被识别为公式块；也忽略写进答题括号里的手写选项字母（`是（C）个`，但 `P(A)` 不受影响）。
  - 旁证原文保存在 `read_b` / `read_c`（没有 `stem` 字段，不会被当作视觉读法），在“更多 → 看两位读者的原始读法”里可见。
- **提示词**：明确要求照抄原卷的错字、漏字、特殊字母顺序与大小写、与常识不符的人名书名；只有原卷印了 ▱ 符号才写 ▱。
- **题干清理**：去掉“（本题满分 N 分）”、无点号题号（`14 如图`）、残留的点号和空括号。
- **HTTP 529**（MiniMax 过载）和 52x 按服务器临时错误重试；原来直接让一张卡只剩一次识读。

### 3. 切题（本地规则，不增加模型调用）

- 忽略“注意事项：1．答题前……”等考试说明编号（需同时有说明标题和说明用语）。
- 去掉 MinerU 行内 HTML（`<sub>12.</sub>`），否则题号不在行首而被漏掉。
- 补出点号丢失的首题（`1 设 z=…`）、装订边裁掉首位数字的题号（`9.` → 19、`0.` → 20）、整个题号被裁掉只剩“（本题满分 6 分）”的题、以及 `14 如图` 这类缺点号的题号。
- “题号重新开始”的判断更稳：忽略 MinerU 重复识别的同一行、孤立的大号码、以及丢了括号的小问 `2.`（后面题号接着原顺序走）。这些原来都会弹出“确认资料结构”。
- 答题空白裁剪先二值化再缩小，且底部空白足够大才裁：原来会把分式分母（V甲/V乙 的“乙”）切掉半截。
- AI 定位漏掉的题号时，若落在上一题的选项行里，向下吸附到真正的题干行，避免把上一题的选项切走。

### 4. 配图与审核减负

- 几道题的图印在最后一题下面同一行时（常见的“13、14、15 题图并排”），按从左到右分给这几道缺图的题，并黄卡提示核对。改前最后一题会**悄悄拿错图**成为绿卡。
- 选择题下方并排 4 张图且没有选项文字时，自动分给 A–D，不再要求人逐个框。
- “大致图像为（ ）”、选项全是图、“数据如下：”、“列联表 / 统计表”都算图像提示，减少“没有发现图像提示词”的误报黄卡（配图规则版本升到 7，旧卡会按新规则重新判断）。
- 由本地规则修复的题号，AI 看到被裁掉的“9”不再误报“AI 看到的题号是 9”。
- 题目在栏底结束、范围延续到下一栏顶部一条很窄的空白时，这条窄条不再“认领”下一题的图（原来会误报“配图冲突”）。

### 5. 稳定性

- MinerU 上传（每次重发完整文件）、下载和接口调用遇到连接中断、超时或 5xx 会重试两次。实测一次对象存储上传卡住就让整份卷失败。

### 6. 前端

- 横长的原卷截图（大多数选择题）改为放在题卡上方、按接近原始分辨率显示，文字大小与右侧排版文字相当，便于逐字对照；竖长截图仍左右并排。
- 选项列数按实际宽度自动降为 2 列或 1 列，不再把 `∠ABD=∠CBD` 这类选项折成两行。
- 大图对照（Space）在上下排布时放大排版文字。
- 顶栏和说明文案改为描述新的“旁证 + 必要时复核”流程；绿卡新增“两种引擎一致”标签。

## 新增 / 变化的配置

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `QB_MINIMAX_ACCOUNT_CONCURRENCY` | 6 | 每个 MiniMax 账号同时请求数（1–8） |
| `QB_SILICONFLOW_ACCOUNT_CONCURRENCY` | 2 | 每个硅基流动账号同时请求数 |
| `QB_MINERU_ACCOUNT_CONCURRENCY` | 1 | 每个 MinerU Token 同时解析的分片数 |
| `QB_HEDGE_AFTER` | 18 | 请求多少秒未返回就发对冲请求；0 关闭 |
| `QB_PARALLEL` | 自动 | 同时读题的题卡数，1–16；手动设置后标记为 `QB_PARALLEL_EXPLICIT=1`，不再自动提高 |

没有数据库迁移。`text_source` 新增取值 `witness`；配图 `source` 新增取值 `row`（按行分配，重读时视同借来的图保留）。

## 已知问题与下一步建议

1. **有手写的卷子仍然最慢、最依赖复核**：MinerU 文字混入手写，旁证很少能逐字一致，仍需同模型复读；同一模型偶尔两次都“改字”（例如都把“图形面积”读成“图形的面积”）而成为绿卡。若能配置硅基流动作为另一家复核模型，独立性会更好。
2. **手写答案偶尔漏进题面**（如填空横线后的手写 `2√3`）。可考虑对“横线/括号后紧跟内容”做本地提示。
3. **AI 定位漏题号**仍是粗粒度（按横带），本次只做了“别切到上一题选项”的保护。
4. **账号并发没有放进设置界面**，目前只能用环境变量调整；安装版用户需要的话可在“设置 → API 与模型”加一个 1–8 的数字框（后端已支持，写入偏好文件后由 worker 在任务边界读取即可）。
5. 本轮没有用整本教材测试“书籍”流程（额度考虑）。书籍路径同样受益于并发与旁证，但切题规则未改。
