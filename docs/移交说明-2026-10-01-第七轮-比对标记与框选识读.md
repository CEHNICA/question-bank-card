# 移交说明：第七轮 比对标记与框选识读（2026-10-01）

分支：`improve/1.10.0`（接在 1.10.1 的 `6ebe58d` 之后）。版本号 `1.10.2`。用户可见的说明见 `docs/release-notes-v1.10.2.md`。

起因：用户看 1.10.1 重读的“高一质量检测一”时提了三件事：

| 用户的话 | 题 | 处理 |
|---|---|---|
| “需要比对的地方标记出来” | 19（x³ / x²，三处分式指数）、2 | 截图上框出 MinerU 那一行并编号，题面上标出那个字 |
| “A 选项内容可以设置一个局部识别的功能” | 11（A 选项被手写 × 盖住） | 新功能“框选识读” |
| “说图片已经加上，但是并没有” | 16 | 确认无图后“别的题认为有一张图属于本题，已加上”没有清掉 |

真实试卷不进仓库（CONTRIBUTING）；测试全部是虚构题目和模拟模型输出。

## 1. 要比对的地方（spots）

“两次识读一致，但 MinerU 在这里读法不同”这条提示来自 `pipeline._settle_objections`：`textnorm.witness_objections` 在读法的 key 和 MinerU 的 key 之间找干净的一对一替换（≤3 字，两边各 3 字相同的上下文），再让裁决模型逐处二选一；选不了的留在提示里。

- **记录**：`read_c`（有裁决时是 `read_c["objection_check"]`，见 `pipeline.spot_record`）多了 `doubtful`：提示里那几处，按提示的顺序，每处带
  - `n`（①②③ 的序号），`reading` / `mineru` / `before` / `after` / `at`（读法在 key 里的位置）；
  - `page_idx` / `bbox`：MinerU 读到这处的那个框（`textnorm.spot_block`，按 MinerU 那边的上下文找；框里有换行时缩到那一行，`_spot_line`）。快照里多了 `witness_blocks`（题目范围内的 MinerU 文本框）。
  - `field` / `start` / `end` / `text`：这处在最终题面里的位置（`pipeline._mark_spot_text` → `textnorm.spot_place`）。
- **定位文字**（`textnorm.spot_place` / `spot_range` / `_raw_span`）：比对时题干和选项是拼成一段读的（`reading_witness_text`：题干去掉表格 + `A.…B.…`），所以选项开头那一处的上下文里有选项字母。定位时按同样方式拼起来找，再映射回字段。key 位置换回原文位置用前缀二分（`_key_offset`），结果必须能 key 回读法本身；不行就在原文里找读法的字符，取 key 位置最近的（偏差 ≤3）。同样的上下文出现两次时，按 `at` 取比对时的那一处。题干有表格时，题干单独找。
- **给页面**：`question_json` 多了 `check_spots`（`pipeline.check_spots`）。只在提示还在时给；存的位置和现在的文字对不上（人改过字）就去掉文字位置，框照留。1.10.2 之前读过的卡没有 `doubtful`：启动时 `library.tidy_saved_cards` 用 `read_c_with_spots` 算一次存进 `read_c`（`read_c` 不在审批哈希里，不影响打勾，不改 `updated_at`）；`check_spots` 里现算只是兜底。
- **前端**（`app.js`）：
  - `cropView(..., { spots })` 在截图上画 `.crop-spot` 虚线框，同一行的几处合成一个框，标签写全部序号；框靠近截图顶时标签放到框下面（`label-below`）。
  - 题面标记 `reviewMarks(q)` = 原来的差异标记 + `spotTextMarks(q)`（`kind: "spot", exact: true`）。
  - 公式里的字：`QB.colourLatex` 用私用区字符占位，转成 LaTeX 后换成 `\textcolor`；占位落在命令名里或跨括号就返回 `null`，整段公式加框。
  - 普通文字经 `tidyText` 去掉空格、软换行后，用 `QB.tidiedMarks` 按非空白字符把标记对到整理后的文字上；对不上（标记只盖住空白）才整段标出。
  - 提示里每处前面加 ①②③（`SPOT_FLAG`）。

## 2. 框选识读（`core/region_reads.py`，模型 `RegionRead`，迁移 `0015_region_read`）

- **接口**：`POST /api/questions/<id>/region-read` `{page_idx, bbox, target}`，`target` ∈ 题干 `stem`、`A`–`E`；框至少 4×2（千分坐标），页码要在卷子里；没有看图服务（`_vision_ready`）时 400，说明去设置里填密钥。同一题只留最新一个（新框会删掉旧的）。`DELETE` 删掉（“关闭”“不读了”）。`question_json` 多了 `region_read`（`latest_json`，卷子详情用 prefetch）。
- **工作者**：网页进程拿不到密钥，只排队。`run_worker` 的主循环和重读通道都调 `process_pending`；靠条件更新认领（queued → running），只会读一次。启动时 `recover_interrupted` 把 running 放回队列。写结果也是条件更新（`status=running` 才写）：读的时候人关掉或重新框了，结果丢掉。
- **读法**：框外留 6，放大到长边 ≥1100 再给主读题模型（`readers.primary_engine`）；提示词要求只誊录印刷字、印刷字上的 × 照样读、看不清写 [?]、选项不写字母。`clean` 去掉 `<think>`、代码块、【】标签、本选项的字母（`A.` / `（A）`）、编出来的配图说明；什么都没有就报“框里没有读到印刷文字”。
- **不直接改题卡**：选项结果点“填入选项 X（打开改字）”，`openEditor(card, q, { prefill })` 把字填进那个选项、加橙色边，人保存才算；题干结果复制到剪贴板（剪贴板不可用时提示手动复制）。
- **页面**：`openPageDialog("read", q)`，只留一个框，上方选“读出来的字填到”（`readTargetGuess`：先选缺的选项）。读的时候题卡轮询（`regionReadPending`）。

## 3. 第 16 题：确认无图后提示还在

`figure_policy` 新增 `FLAG_ROW_FIGURE`、`FLAG_FOREIGN_FIGURE` 和 `DECISION_FLAGS`。这两条提示问的是“这张图要不要”，人做过决定就答完了：

- `views._apply_figure_review`：`source == "human"`（确认无图、亲手选图）时去掉这两条。撤销“确认无图”、图放回来时，放回的图来源是 `other` / `row` 的，提示加回来。
- `library.tidy_saved_cards`：配图已由人决定、却还留着这两条的卡，启动时去掉；只因为这一条标黄的变回绿卡。

## 4. 启动整理里顺带的

- 选项里存着“（原卷此处为配图，无印刷文字）”这类说明、没审过也没改过的卡（1.10.0 读的）：
  - 选项本身是图（`figures` 里有这个选项）→ 只去掉说明；
  - 另一次识读（`read_a` / `read_b`）读出了这个选项 → 补上，提示“只有一次识读读到，已补上，请对照原卷核对”（那次识读写的是“（图片）”之类，或者和别的选项重复，不算）；
  - 都没有 → 去掉，提示“没有读出来，请对照原卷补上”，标黄。

## 没做的

- 截图上的框是 MinerU 的那一行，不是那一个字：MinerU 只给到文本框，再细要另做字符级定位。
- 框选识读只能填一个选项或复制题干的一段，不能直接替换题干里的某几个字。

## 补：1.10.3 大资料提速

用户说必修一（673 题）打开审核页卡。用用户数据库的只读副本测（会话临时目录，没进仓库）：

| | 1.10.2 | 1.10.3 |
|---|---|---|
| `GET /api/papers/<id>`（审核页数据） | 2.9–3.4 s，681 次查询 | 0.45–0.5 s，8 次查询 |
| `GET /api/papers`（左栏列表，每 15 秒一次） | 1.5 s | 首次 1.4 s，之后约 60 ms |
| 打一个勾（`POST …/approve`，返回带计数的 paper） | 1.5 s | 60–75 ms |
| 浏览器里从打开到第一张卡 | 7.5 s | 1.6 s |

- `figure_policy.reusing_reviews()`：只读视图里每张卡的配图检查只推导一次（按对象缓存，返回深拷贝）；不在这个上下文里一切照旧，改过卡再问会重新算。
- `library.live_publications_prefetch()` + `publication_state`：入库记录一次预取，不再每张卡查一次。
- `views.card_verdicts`：每张卡“审批是否有效、配图是否拦住”按数据库原始行的指纹（整行原文 + 分组标题/序号 + 试卷显示名）记在进程里；行有任何变化就重算，包括不更新 `updated_at` 的 `.update()`。审核页传入已载入的行，直接算。
- 前端：`.card { content-visibility: auto }`（卡片原本就 `overflow: clip`，不会多裁掉东西；当前卡和正在改字的卡保持 `visible`）；`renderCards` 用 Map 找卡；`fitOptions` 先量完再改类名，避免逐个强制重排。
- 试过把 KaTeX 结果按公式缓存，首屏没有收益，没留。
- 测试：`backend/core/test_v1103_speed.py`、`frontend/test_speed.js`。
