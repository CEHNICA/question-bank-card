# 题有据 1.12.2

补丁版。修五件在这台机器上真实撞到的事，主题只有一个：**别再让“看起来成功”冒充成功。**

## 1  自动切题会少切，而它以前不吭声

24 题的卷子交上来两张题卡，状态写着“待你终审”。这不是切题崩了——它安静地少切了：
缺号检测只看两个已经定位到的题号之间的洞，只切出 1、2 时，后面没有任何东西可以比，
3 到 24 就永远不会被提起。纯扫描件更彻底：一句文字都读不出来，机器其实没有任何依据
说自己切全了，可它照样说“待你终审”。

现在每次自动切题结束都要对一次账：原卷上真的印着哪些题号（`segment.printed_numbers`），
和真的切出哪些题卡对一遍，结论有四种，界面上长得不一样：

| 结论 | 什么时候 | 状态 |
| --- | --- | --- |
| 一题没切出 | 硬失败 | 任务失败，写明本地为什么没切出来 |
| 切题不全 | 卷面印着却没切出，点名缺哪几题 | 标签“切题不全”，卷名下有一行直说的话 |
| 切题待核对 | 扫描件读不出文字，无法判断 | 标签“切题待核对”，请对照原卷核对题数 |
| 切全了 | 卷面印着的题号每一个都切出来了 | 保持原来的“待你终审” |

那句“切题不全 / 自动切题失败”下面有一个「在原卷上补切」按钮，一点直接进原卷框题：
已经是手工卷就直接开框，还是失败状态就先转手工再开框。原卷和已有题卡在两条路上都保留。

老师自己把缺的题框出来之后，横幅会跟着缩小：框完最后一题，横幅自己消失。**已经切坏的
旧资料不会被回头修改**——这次只保证以后的流程不再骗人。

## 2  等 MinerU 时的一次心跳，曾经能杀死整轮解析

`worker.log` 里两次 `OperationalError: database is locked`，栈是
`mineru.request_extract_file → pipeline.heartbeat → _paper_heartbeat`：等云端的时候另一个
连接正在写库，心跳一撞上就抛出，一个本来完全正常的云端任务被判成失败。

心跳是整轮运行里唯一没有人等待的写入。丢掉它只会让“正在解析”多停几秒；让它冒出去赔上
整轮。所以：心跳的锁冲突被记一笔然后丢掉，下一次心跳和这一轮自己的检查来决定这份卷还要
不要。同时 SQLite 改成 `BEGIN IMMEDIATE`（`transaction_mode: IMMEDIATE`）——默认的延迟
事务是先当读者、第一次写的时候才要写锁，中间只要别人写过就直接报错，busy handler 根本不会
被调用，`timeout: 30` 是白设的。

## 3  选了没配密钥的服务，原来直接失败

“所选服务没配密钥就换用另一家”，以前被一刀切地禁止了：老师只填了魔搭、选了 MiniMax，
照片就以“没有配置所选主读模型的 API Key”失败，而界面上先说“可以读”。

`selected_services_only` 的职责收窄为**守住已经发出去的请求**：一个已经在回答问题的服务，
失败时不能换到别家（那是第二次花钱，还可能留下一张读了一半的卡）。而一个**从来没配过密钥**
的服务不是一次失败的请求——换到已配置的服务才是对的。现在会换，并且说清楚：

- 读题按钮会写成「这次用 魔搭 读」，`/api/status` 的 `reader_readiness` 带上 `used`；
- 真正一个服务都没配时，句子变成“本机没有已配置的服务”，不再假装有备选；
- 换服务之后不会自动替用户改用付费模型，模型和角色的选择一个字都没动（AGENTS.md）。

## 4  API 配置窗口关闭“卡一下”——先量了才改

在真实 Chromium 里量了 20 次（仓库自己的 styles.css 和 credentialDialog 标记）：

| 变体 | 关闭那一帧的间隔（中位数） |
| --- | --- |
| 现在的代码 | 3.0 ms |
| 去掉 `::backdrop` 模糊 | 2.85 ms |
| 关闭逻辑延后一帧 | 7.0 ms（更慢） |

**渲染不是原因**，两个原本的怀疑对象都被数据否掉了。真正的原因是等待：模型设置没保存时，
关闭会先等一次 `/api/settings/models`，**再等一次 `loadStatus`**，两次往返串行，中间屏幕上
什么都不显示——本机后台任务正在写库时，这段时间足够长，长到像是点了没反应。

改的是两件事：关闭只等保存这一次往返（状态刷新挪到窗口关掉之后），以及等待期间把“正在
保存后关闭…”写出来并禁用关闭按钮。保存失败或老师选择“继续设置”时，按钮和提示都会复原，
不会把那个卡住的窗口留在屏幕上。

## 5  同一家 MiniMax 的密钥，不用填两次

读题和标签、答案各存一份加密文件，所以同一个 MiniMax Key 过去要粘贴两次。合并的是
**服务与密钥**：答案面板在服务商是 MiniMax 时多出一块，共用一个按钮把读题那份复制过来。

规则：

- 只合并 MiniMax。魔搭、硅基流动只读题，DeepSeek、豆包只管答案，把它们并到一起等于凭空
  造一个本机没有的能力。
- 模型和角色的选择**仍然分开**。共用密钥不等于替你改用付费 API（AGENTS.md）。
- **绝不自动填**。答案这边已经有一份独立密钥时，按钮写的是「改用读题的 MiniMax 密钥」，
  不是“共用”，点下去才算数，随时可以「改用独立密钥」改回来。
- 读题侧账号池里有多条时取第 1 条，并且这句话写在界面上。
- 共用后“已测通”会被清掉：换的是凭据，不是配置。
- 读题那份永远不动，密钥也仍然只经原有的两个适配器读写，不新增解密路径。
