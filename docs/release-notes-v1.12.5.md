# 题有据 1.12.5

本次是一次「按老师反馈逐条修」的版本：修一个从 1.12.1 起一直坏掉的功能，删三条不实的提醒和一套没人用的功能，再把切卷的卡顿去掉。

## 「改字」点了没反应（1.12.1 起一直坏）

展开一张题卡，点「改字」，什么都没发生；控制台里躺着一条报错。**从 1.12.1 到已发布的 1.12.3、以及本机的 1.12.4，全都带着这个问题**，只是没人报上来。

更糟的是：点了没反应之后，这张卡在**本次会话里再也点不开改字**了，只能重启程序。

这次不只修好了，还改了处理方式：改字面板以前是在构建过程中崩掉的，异常被悄悄吞掉，所以界面上只剩下"点了没反应"。现在一旦出错会当场告诉你，并把那张卡恢复成没在改的样子。

## 删掉「截图里还露出了第 N 题」

这条提醒一直在，但你核对的 153 张卡里它出现了 6 次，基本都是错的。

原因查清楚了：它本来设计成"两位读者都看到才提示"，可是双读这条路早就被关掉了，实际一直是**一个模型自己说完自己信**。而且它写的是"范围可能需要调整"，等于让你去重切那些本来切对了的题。

新识读的卷不会再出现这条。已经入库的题卡上留着的旧提醒按原样保留，不追溯清理——它们虽然不准，但记录着当时发生过什么。

同一族里的另一条「AI 看到的题号是 N，请确认」**保留**：那条是真的在核对题号对不对。

## 「批量处理题卡…」整套删掉

工具菜单里的「批量处理题卡…」连同它的选择栏、圆形选择框、批量识读、批量删除、Delete 键和 Ctrl/Shift 多选，一起删除。

题号左边现在只剩一个方框，就是打勾通过——不用再分辨"这个圆的是选中准备删，那个方的是打勾通过"。

每张卡自己的「更多 → 让 AI 重读这题」和「删除这张卡」都还在，单独操作不受影响。

## 工具菜单新增「一键通过所有题目」

把这一卷里**能**通过的题一次入库，过不去的逐条说明原因。

- 先问一句，确认了才动
- 结果面板先报「已入库 N 道」，下面逐条列出每道过不去的题和原因（题号 + 具体卡在哪一步）
- 已经入库的题不会被重复算成"过不去"

这次顺手修掉一个老毛病：以前批量通过是**静默跳过**所有过不了的题，界面上看不出发生了什么，像是"点了没用"。原因是一张绿卡只要身上还带着任何一条待核查提醒（包括跟配图无关的），内存里就会被改回黄色然后被悄悄跳过。现在这些都会逐条报出来。

## 「已完成」统一改成「已入库」

审核页的筛选页签、进度条、标题行、快捷键说明，原先一处叫「已完成」、另一处叫「已入库」，同一件事两种说法。全部统一成**已入库**，鼠标停上去写明它的准确含义：题库里已经有这道题的记录（打了勾的，或原来就放着的）。

顺带修掉一处自相矛盾：一份卷子已经全部处理完时，顶部原本会写「25 道题，N 题需要核查」，而 N 本该是 0。

## 切换试卷不再卡

原来切到一份 25 道题的 PDF 卷要等 190ms，看不出在做什么；现在 30ms 左右。

真正的原因不在缓存：打开一份卷子时，每道题的原图都会被重新解码一遍、重新算一遍哈希，**整份 PDF 被重复读了 25 次**。现在原卷的哈希只算一次（文件一变就重算），题卡裁好之后的尺寸和哈希也记下来；文件真的被动过（被删、被截断、被换掉）仍然会重新检查、重新生成。

界面上也不再先清空题卡再等数据——换卷时旧卡留在屏幕上压暗、不接受点击，新题到了整批换掉。一屏空白看着就是卡死了。
