# 1.26.38：把全软件的灰按钮扫了一遍：剩下的最后一处不吭声的，已经修好

这一版没有新功能，只有一件事：**把整个软件里所有「灰着的按钮」扫了个遍**，看每一个是不是都开了口。

## 一、怎么扫的

不是靠看截图，是**真浏览器里把软件跑起来**扫的：

1. 先把软件里所有**弹窗**和**折叠面板**都打开（不然藏在里面的控件根本扫不到）；
2. 把所有灰控件逐个过一遍；
3. 过的时候判两件事：**它是不是真能看见**，以及**它带不带说明**。

第二条判据是这轮的关键。头一遍扫完报了 20 个「灰着还没说明」，看着像一大片遗留问题。
但加上「看不看得见」这一判，**19 个直接出局** —— 它们整条工具条是藏着的（比如资料库页那排批量操作条、
入库按钮），老师根本看不见，压根不是问题。剩下能看见的灰控件有 42 个，
挨个看过之后，**只剩 1 个真的一言不发**。

## 二、剩下那一处：重新切题预演里的「确认并应用重新切题」

这颗按钮在「重新切题」的预演弹窗底部。它灰的时候，老师看到的就是一个**没有半句话的灰按钮** ——
不知道是在算、在等自己勾确认框、还是软件卡住了。

**这一版给它配了两套说明：**

| 什么时候灰 | 鼠标停上去看到的话 | 按钮旁边一直挂着的小字 |
|---|---|---|
| 正在算预演 | 正在按最新规则生成只读预演，等它算完就能确认应用。 | 正在算预演，算完就能应用 |
| 算完了，还没勾确认框 | 先勾上上面的确认框，看完这次影响才能应用重新切题。 | 先勾上确认框 |
| 预演没算出来 | 这次预演没算出来，没法应用重新切题。先关掉这个窗口再试一次。 | 预演没算出来 |
| 服务端不给做只读预演 | 服务端这会儿不认只读预演，没法在这里应用重新切题。 | 服务端不认只读预演 |
| 正在应用 | 正在应用这次重新切题，别重复点。 | 正在应用 |
| 可以应用了 | 按预演结果应用这次重新切题。 | （这行小字自动收起来） |

## 三、为什么不能只写悬停说明

**按钮灰着的时候，浏览器压根不发鼠标事件给它** —— 悬停气泡根本弹不出来。

所以只在按钮上挂一句悬停说明，等于**老师什么都看不到**。这跟上一版挖出来的坑是同一类：
话术写得再漂亮，控件收不到它，老师那边还是一片安静。

因此这一版除了悬停说明，还加了一行**一直看得见**的小字。（软件里本来就有一处这么办 ——
资料库页那个「批量生成标签建议」，所以是照着已有的规矩来的，不是新发明。）

## 四、这一版的验收检查

加了 **20 条「改坏了就废」的检查，全部被挡住**。

写这批检查时当场发现一个漏洞，值得记下来：

**第一条检查写得太松** —— 它只要求「那颗按钮附近有 title 字样」，结果匹配时会跨过整页，
**匹配到别的按钮的说明**也照样通过。这种检查等于没写。
已改成：**先取出那颗按钮自己的标签，再在标签里找 title**，认准那颗按钮，不认别人。

（这跟上一版那条教训是一脉相承的：验话术函数 ≠ 验按钮挂上了话术；验「附近有字」≠ 验「是它自己的字」。）

## 五、真机验过

**在哪验的**：老师真题库的一份副本。**老师的真库一个字没动。**

真浏览器里把预演弹窗开起来，把三个状态一个一个走了一遍：

- **正在算**：按钮上写「正在按最新规则生成只读预演，等它算完就能确认应用。」，
  旁边那行写「正在算预演，算完就能应用」，两行都看得见；
- **算完、还没勾确认框**：按钮上写「先勾上上面的确认框，看完这次影响才能应用重新切题。」，
  旁边那行写「先勾上确认框」；
- **勾上确认框**：按钮变亮、**能点了**，悬停说明换成「按预演结果应用这次重新切题。」，
  旁边那行小字**自动收起来**（不该挡路的时候就不挡）。

三个状态说得都是不同的话，不存在「换了状态还是同一句」。
