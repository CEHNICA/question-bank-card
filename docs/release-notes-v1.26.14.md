# 1.26.14：测试连接跟着每一家自己的卡片走

老师看了 1.26.13 的界面，说：

> 这个测试啊，应该跟在每一个API后面，你觉得呢？

**同意**，而且这不是偏好问题 —— 三个主流项目都是这么摆的：Chatbox 的 Check 按钮在
服务商自己那一页里，LobeHub 的「连通性检查」在服务商卡片里，Cherry Studio 的检测
也在对应服务商名下。测试按钮和它要测的密钥分开摆，老师就得先想一遍"刚才那个按钮
说的是谁"。

## 现在

**看图读题（读题侧）**：勾了哪家，下面就是那家的卡片，卡片里依次是

```
MiniMax API Key  填写可用于视觉模型的 Key              已保存 1 个
  [已保存的那条密钥]  👁
  新的 Key（留空就不改）
  [粘贴 MiniMax 开放平台里复制的 API Key]
  模型名称        API 已配置
  [MiniMax-M2.7]
  ─────────────────────────────────────────────
  □ 我同意这一次测试（会向服务商发一张软件自己画的合成图）
  [ 测试连接 ]
```

魔搭、MiniMax、硅基流动**每家的卡片里各有一个自己的测试按钮**：测的就是眼前这家，
结果也留在自己卡片里，不会串。换了别家再看回来，上次的测试结果还在。

**生成标签和答案（答题侧）**：「连接测试」那一块也搬进了当前这家的卡片里（DeepSeek
的卡片里就是 DeepSeek 的测试），不再是一张单独的卡片飘在下面。

**MinerU**：还是没有测试按钮 —— 它的官网没有公开的 Token 验证接口，测不了。卡片里
写清楚了：保存成功就表示已配置，实际能不能用看切题任务的返回。
