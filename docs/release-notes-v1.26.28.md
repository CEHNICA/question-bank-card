# 1.26.28：给这个项目装上一套「专业造软件」的环境

**老师原话：「现在利用一个类似虚幻引擎，制造游戏的这么一个软件，将这个项目专业化。」**

虚幻引擎给做游戏的人的不是「更好的游戏」，是一套**造软件的工程环境**：打开就有工程、
一编译就过、测试自动跑、打包一条命令。题有据也该有这一套。

这一版没有新功能 —— 是把「怎么改、怎么验、怎么发」这件事做专业。

## 一、现在怎么干活

```powershell
.\dev.ps1 setup     # 装好开发环境（虚拟环境 + 依赖 + 工具）
.\dev.ps1 check     # 规范 + 类型 + 三组测试全跑一遍
```

不用再靠记性拼命令。

## 二、四道门禁，每次提交自动跑

| 门 | 管什么 |
| --- | --- |
| **ruff** | 写错的、写漏的、写重复的 |
| **ruff format** | 排版统一（358 个文件按同一套规矩排过了） |
| **mypy** | 类型对不对、会不会拿 None 直接用 |
| **eslint** | 前端：没定义就用、声明了没用、循环里的坑 |

全在 GitHub Actions 上跑，**不过就不算合进去**。

## 三、发版不用再手动一步步来

改版本号 → 打 `v*` 标签 → 推上去，CI 自动：装打包器 → 跑全套检查 → 打包 →
审计（查有没有把数据库、试卷、凭据带进去）→ 建 Release → 传附件。

标签和源码里的版本号对不上，CI 直接停手 —— 不会装出一个版本号是假的包。

## 四、门禁真抓出了两个问题

1. **「去右边面板核对」这个按钮点了没反应** —— 代码里引用了一个根本不存在的变量，
   点一下就报错，什么也没发生。这个 bug 一直没人发现。
2. **表格导出里有一段闭包抓着循环变量** —— 当时恰好用对，以后挪一下位置就会静默出错。

还清掉了没人用的死代码、一个旧流程留下的函数、几处重复的键。

## 五、顺带修了一个会**悄悄丢东西**的问题

1.26.27 那一版把标签「不再按类型分家」放开了 —— 拖放能挂、并列能排、
标签管理页的「设置父标签」也能选别类的上级了。

但**编辑标签时那个「上级标签」下拉还按类型筛**。后果是：别类的上级根本不列出来，
老师改个名字一保存，那条上下级关系就被抹掉了 —— **界面上一点提示都没有**，
标签还叫那个名字，看上去什么都没变，关系却没了。

这一版：

- 上级下拉不再按类型筛，和标签管理页那套规矩统一；
- 已经挂着的那种一律留着（哪怕它已停用）；
- 同名的两颗标签，下拉里把类型标出来（「分类讨论（解题方法）」），才分得清是哪一颗；
- 自己的后代不再被当成上级（跨类型的也算了）—— 选上去会成环。

新增一条**真跑出来**的测试：打开编辑窗口 → 看下拉里那颗别类的上级在不在、在不在选中
→ 真按保存 → 看发出去的上级还在不在。三条改回老样子的变异全被它挡住。

## 六、类型检查：先从干净的模块做起

mypy 挑出的 **264 条**逐条记在 [类型检查待办](类型检查待办.md) 里。
