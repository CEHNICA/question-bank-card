# MinerU 云 API：当前规则与故障排查

调查日期：**2026-10-03**。面向中国区 `mineru.net` 云服务，依据公开官方页面、官方生态仓库及一次自制文件的免登录小测试。未登录账户、未读取密钥、未上传用户资料；精准 API 未做真实识读。

题有据使用需要 Token 的**精准解析 API**，取得结构化结果来切题、找图和保存出处。当前 API 管理页写明单文件不超过 **200 MB、200 页**；每天 **1000 页是最高优先级额度**，超出后降低优先级，并非“到 1000 页就不能解析”。[官方 API 文档](https://mineru.net/apiManage/docs)

官网当前表示暂无商业化收费计划，但仍有限流、每日文件数量和账户条件；不承诺永久免费或始终可用。[官方限流与收费说明](https://mineru.net/apiManage/limit)

## 当前页面与旧文档有差异

当日两个官方入口同时可访问，内容并不一致。题有据按 API 管理页较保守的限制处理新资料。

| 项目 | 当前 API 管理页 | 旧文档入口 |
| --- | --- | --- |
| 单文件大小 | 200 MB | 200 MB |
| 单文件页数 | 200 页 | 600 页 |
| 每账号每日最高优先级页数 | 1000 页，超出后降低优先级 | 2000 页，超出后降低优先级 |
| 本地文件上传链接申请 | 具体接口章节规定每次最多 50 个 | 部分旧说明、模式总表仍显示批量 200 个 |
| 入口 | [apiManage/docs](https://mineru.net/apiManage/docs) | [doc/docs](https://mineru.net/doc/docs/) |

当前页面的模式总表也写“批量最多 200 个”，但 `file-urls/batch` 和 URL 批量提交的具体章节都写最多 50 个。调用时以具体接口的 50 个为保守上限，不据此扩大批量。

这些是 **2026-10-02 调查、2026-10-03 再次核实的文档差异**；页面没有说明准确生效日期，不能由此声称服务是在某一天统一切换限制。官方生态仓库的当前说明也列出精准 API 的 200 MB / 200 页限制。[MinerU-Ecosystem](https://github.com/opendatalab/MinerU-Ecosystem#-supported-apis)

## Token、额度与费用

精准 API 使用 `Authorization: Bearer <Token>`。Token 在 [API 管理页](https://mineru.net/apiManage/token) 登录后创建；凭据由使用者在题有据的“设置 → 服务与密钥”中填写，不发给 AI、不放进公开日志。

**有效期以 Token 管理页显示的实际到期日期为准。** 当前公开 API 文档只区分 Token 错误 `A0202` 与过期 `A0211`，未给出适用于所有账户的固定有效天数。2026-01-24 的 [旧讨论 #4412](https://github.com/opendatalab/MinerU/discussions/4412) 是用户提出的 14 天续期诉求，不能作为当前“所有 Token 每 14 天过期”的依据。

用户本次提供的官网通知截图显示“API Token 有效期”从 **14 天延长至 90 天**。这是通知截图证据；2026-10-03 匿名获取的公开 API 文档中未找到 90 天说明，未登录核验已有 Token 是否同步延长。软件不应提示固定 14 天更换，也不能替用户推算所有凭据的到期日，仍以 [本人 Token 管理页](https://mineru.net/apiManage/token) 为准。

管理页的公开前端按服务返回的 `expired_at` 显示到期状态，并包含账户验证与手机号绑定流程；是否需要完成某项验证，以本人账户页面及创建 Token 时的提示为准。本次没有登录账户，也未读取任何 Token。

### 配置保存与真实可用分开

本次未在当前公开文档中找到可供第三方软件无任务验证 Token 的 `/quota` 接口约定。题有据 **1.10.15 起停用旧的未公开额度预检请求**：保存 MinerU Token 时只做格式校验与本机加密存储，报告“已配置，未核验”。这不证明 Token 有效，也不证明服务故障；实际可用性以真正的识读任务及本人账户页面为准。已有任务若明确返回 `A0202` 或 `A0211`，仍按真实错误说明需要检查或更换凭据。

| 规则 | 当前官方公开说明 | 使用时应注意 |
| --- | --- | --- |
| 优先级页数 | 每账号每日 1000 页最高优先级，超过后降低优先级 | 不与每日文件数混淆，不当成硬停用额度 |
| 提交频控 | 单文件、文件上传批量、URL 批量提交共用 50 个文件/分钟 | 按文件数计，不是每个入口各 50 次 |
| 每日文件数 | 每个用户每天最多 5000 个文件，其中 HTML 最多 100 个 | 仍可能达到每日数量上限，账户页为准 |
| 查询频控 | 单任务与批量获取结果共用 1000 次/分钟 | 排队时适度轮询，不反复重新上传 |
| 商业化 | 当前暂无商业化收费计划 | 不保证未来规则不变，不把“免费”解释成不限量 |
| 动态限制 | 服务商可依系统负载调整限流 | 遇限流或队列满时稍后重试 |

以上频控、每日文件数和商业化说明来自 [官方限流页](https://mineru.net/apiManage/limit)，优先级页数来自 [官方 API 文档](https://mineru.net/apiManage/docs)。公开规则不能代替单个账户的权限、额度或服务状态。

## 精准解析与免 Token 轻量解析

| 能力 | 精准解析 API | Agent 轻量解析 API |
| --- | --- | --- |
| 鉴权 | 需要 Token | 无需 Token，按 IP 限频 |
| 模型 | `pipeline` / `vlm` / `MinerU-HTML` | 固定轻量 `pipeline` |
| 单文件限制 | 200 MB、200 页 | 10 MB、20 页 |
| 提交方式 | 单文件与批量 | 单文件 |
| 结果 | ZIP 中的 Markdown、JSON，可额外导出其他格式 | Markdown 的 CDN 链接 |

来源：[官方模式对比](https://mineru.net/apiManage/docs)。题有据保留原卷位置、切题和配图需要结构化结果，因此不能直接把轻量接口的 Markdown 当作同等替代品。免 Token 也不意味着无限使用或不向云端发送资料。

### 网友说的“CLI 可用”可能是三种不同入口

| 入口 | 是否使用云 Token | 能取得什么 | 对题有据的意义 |
| --- | --- | --- | --- |
| 本地开源 `mineru-kit parse` | 本地模式无需官网 Token；显式 `--remote` 才访问远端 | 4.0 中间 JSON / ZIP，含原页号、块坐标、公式和图块 | 可做独立本地 OCR 后端，需要安装依赖和模型、适配新协议 |
| 官方云 CLI `mineru-open-api extract` | 需要，与精准云 API 相同 | 云结果包、Markdown / 内容列表 JSON / 图片等 | 是现有云接口的包装，不能绕过 Token、限流或同一云服务故障 |
| 官方云 CLI `mineru-open-api flash-extract` | 无需，按 IP 限频 | 轻量 Markdown，无完整原页块坐标契约 | 可辅助手工题框后的文字识读，不能直接替代整卷定位与切题 |

官方云 CLI 的 Windows x64 / ARM64 资产来自 [官方安装脚本](https://cdn-mineru.openxlab.org.cn/open-api-cli/install.ps1)；本次仅将 x64 文件下载到临时目录，未执行安装器、修改 PATH 或登录。实测 `version` 返回 **v0.5.9**（构建于 2026-04-10），`--help`、`extract --help`、`flash-extract --help` 均能在本机 Windows 运行。官方生态仓库的 `VERSION` 文件写 v0.1.0，不能当作 CDN 二进制的实际版本。[官方云 CLI 说明](https://github.com/opendatalab/MinerU-Ecosystem/tree/main/cli/mineru-open-api)

这个二进制的 `extract --help` 仍写 600 页，与当日 API 管理页及当前仓库 README 的 **200 页**不一致；使用时按 API 管理页限制。`flash-extract --help` 又同时写“图片、表格、公式为占位符”和公式识别默认开启，因此不能只读帮助就保证公式完整。

**免登录通道已做一次实际验证。** 官方 [生态仓库](https://github.com/opendatalab/MinerU-Ecosystem)明确说明 Flash 免费、免 API Key、每次最多 20 页 / 10 MB。2026-10-03 用自制的一页 PDF（994 字节、两行英文题干、分式与指数、简单三角形），隔离空用户配置目录并移除凭据环境，执行一次 `flash-extract --ocr --formula --table`：6.86 秒返回 Markdown，退出码 0；两行题号正文识出，几何图只剩 `<!-- image-->`，分式中的分母和指数丢失，未返回 bbox 或结构化原页号。未记录各阶段原始 HTTP 状态码，不把退出码写成 HTTP 200。测试只证明当时的匿名 Flash 通道能够处理这一个合成文件，不能证明精准 v4 API 已恢复、用户账户可用或数学试卷识读可靠。

本地开源版已发布 **4.0.10**（2026-09-29），与上述云 CLI 是两个独立产品。4.0 在 Windows 的 **Basic 档**使用 ONNX / CPU 小模型，官方说明支持 OCR、公式与表格；无需 NVIDIA 显卡或官网 Token。Standard / Advanced 加用 VLM，速度与内存取决于引擎；本机 Intel UHD 770 的性能尚未实测，不能因为支持 llama.cpp 就承诺流畅。[官方发布](https://github.com/opendatalab/MinerU/releases/tag/mineru-4.0.10-released)、[档位与环境](https://opendatalab.github.io/MinerU/usage/tiers/)

4.0 的一次性转换入口应使用 `mineru-kit parse input.pdf -o result.zip --tier basic --format zip --ocr-mode auto`。其默认全页，ZIP 含 `middle_json.json`、`structured_content.json`、Markdown 与素材；中间协议的页号从 0 开始、bbox 为 0–1，不能当作云 v4 的内容列表直接读。`mineru parse --json` 是含继续阅读信息的文档库命令响应，PDF 默认前 10 页，也不是完整内容列表。新版结构需单独适配并做原页坐标验证。本次未安装本地模型、未执行该转换指令。[输出协议](https://opendatalab.github.io/MinerU/reference/output_files/)、[4.0 迁移指南](https://opendatalab.github.io/MinerU/reference/migration_4/)

## 本地文件上传与结果格式

题有据的云解析沿用标准 v4 接口。公开流程如下，适用于 PDF、Office 文档和图片；实际支持格式以官方页面为准。[官方接口文档](https://mineru.net/apiManage/docs)

| 步骤 | 接口或动作 | 关键约定 |
| --- | --- | --- |
| 申请上传链接 | `POST /api/v4/file-urls/batch` | 请求提供文件名等信息；每批按最多 50 个处理 |
| 上传文件 | 对返回的地址执行 `PUT` | 链接有效 24 小时；文档说明无需设置 `Content-Type` |
| 开始解析 | 文件上传完成后服务自动提交 | 无需再调用单文件创建任务接口 |
| 查询结果 | `GET /api/v4/extract-results/batch/{batch_id}` | 等待各文件状态完成，失败则看 `err_msg` 等信息 |
| 下载结果 | `full_zip_url` | 下载并校验结果 ZIP，再读取需要的结构化文件 |

直接 URL 解析则使用 `POST /api/v4/extract/task` 与 `GET /api/v4/extract/task/{task_id}`。官方提示 GitHub、AWS 等境外文件 URL 可能在云端读取超时；网页在本人电脑可打开，不保证 MinerU 服务能读取该地址。

对于非 HTML 的精准解析结果，当前云 API 文档说明：

- `full.md` 是 Markdown 结果。
- `*_content_list.json` 是内容列表，用于文字、公式、图片等结构化内容。
- `layout.json` 对应中间处理结果；`*_model.json` 对应模型推理结果。
- HTML 结果有所不同，通常提供 `full.md` 与正文 `main.html`。

来源：[云 API 结果字段说明](https://mineru.net/apiManage/docs)。官方还链接到 [开源输出格式说明](https://opendatalab.github.io/MinerU/reference/output_files/)；开源软件的版本、API 和目录格式会演进，不能把其本地新版接口直接当作云端 v4 契约。

题有据需要校验取得的是有效结构化包；空包、损坏 ZIP、缺少所需内容列表或无法对应原卷的结果，应报告具体错误。下载成功、HTTP 200 或得到一份 Markdown，都不能代替切题与位置核对成功。

长 PDF 应在本机实际拆分后再上传，保证每个文件符合页数与大小限制；不是给超限原文件加一个页码范围就认定已满足单文件限制。题有据的书籍/讲义默认按 100 页分片，超过单文件页数限制的试卷也需分片。

## 看到错误时，先分清原因

| 错误或现象 | 官方含义或合理分类 | 下一步 |
| --- | --- | --- |
| `A0202` | Token 错误、鉴权未通过 | 检查凭据填写、Bearer 格式及本人账户页面；必要时在官网重新创建，不直接断言过期 |
| `A0211` | Token 过期 | 使用者到官网换 Token，再在题有据设置中更新 |
| `-60005` / `-60006` | 文件大小 / 页数超限 | 按 200 MB / 200 页以内压缩或拆分 |
| HTTP `429` | 请求频率受限 | 降低频率，按提示等待；轻量接口也有 IP 限频 |
| `-60009` | 提交队列满 | 等待后重试，避免不停重新上传 |
| `-10001` / `-60007` | 服务异常 / 模型服务不可用 | 稍后重试，保留脱敏后的具体错误 |
| `-60010` | 解析失败 | 按返回原因检查文件，必要时重试；不把所有失败归为密钥问题 |
| `-60018` / `-60019` | 每日任务数量 / HTML 文件额度达到上限 | 查看本人账户额度，等额度恢复；不是 1000 优先级页数的直接证明 |
| `-60008` | 云端读取文件超时 | 检查云端是否能访问文件地址，或使用本地文件上传流程 |
| `-60012` / `-60013` | 任务不存在 / 当前凭据无权访问任务 | 核对任务及账号，不反复查询错误任务 |
| HTTP 200，但返回错误对象 | HTTP 成功不等于任务成功 | 检查 `code` / `msgCode`、`success` 与错误说明 |
| 结果下载、ZIP 或结构校验失败 | 传输或结果结构问题 | 明确报告哪个环节失败，不创建假题卡、不自动通过 |

错误码来源：[官方错误码表](https://mineru.net/apiManage/docs)。网络超时、账户鉴权、限流、每日文件数、模型故障和结果校验是不同问题，处理方式应分别说明。

题有据的状态页表示本机应用与凭据配置；它不会仅凭“填了密钥”就证明云识读可用。服务受影响时，示例教学、已有题卡核对、出处、正式题库和组卷仍可使用；解析新原卷要等所需服务可用。

## 近期故障证据的边界

在官方仓库中，用户于 2026-06-16、06-28 报告新建 Token 仍返回 `A0202`；2026-08-14 还出现网页版登录后无法保持登录状态的报告，09-06 有其他用户补充相同现象。[#5133](https://github.com/opendatalab/MinerU/issues/5133)、[#5187](https://github.com/opendatalab/MinerU/issues/5187)、[#5395](https://github.com/opendatalab/MinerU/issues/5395)

这些是**官方仓库里的用户报告**，本次查看没有找到维护者确认其根因或修复时间的回复，也未找到覆盖全站的正式停服公告。不能据此认定“MinerU 全面关停”，更不能认定某位用户的问题就是登录同步、未实名或 Token 过期。

本次能核实的是公开页面、接口与输出约定，以及上述一次匿名 Flash 合成文件测试；**未读取本机密钥、未登录账户、未提交用户原卷、未发起精准 API 识读**。因此不宣告精准云服务已恢复或当前用户账户已经可用。实际失败原因仍应结合本人操作时的具体错误与账户提示判断。

## 本次软件与验证方向

- 按当前 200 页限制分片，保留原卷页码对应关系；长资料的失败分片可以独立重试。
- 对鉴权、过期、限流、每日任务数、服务失败和结果损坏分别提示，不把所有问题都叫“MinerU 用不了”。
- 保存 Token 只做格式校验与本机加密存储，停用未公开额度接口的无任务预检；不把“已配置，未核验”说成服务已就绪。
- 检查 HTTP 与业务错误对象，校验结果 ZIP 与内容列表；云端出错时不把错误页面当成题目内容。
- 使用模拟响应、临时数据和离线结果包验证分片与错误处理。它们验证软件处理流程，不证明真实云端当前可用，也不代替真实识读质量测试。
