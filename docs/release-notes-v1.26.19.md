# 1.26.19：修掉自动备份把磁盘塞满的毛病（我自己写的功能出的事）

**这一版修的是 1.26.17 那个"每周自动备份"里的两个错。两个错都在同一个地方：
备份包把自己的旧备份包也打了进去。**

## 一、出了什么事

在老师的电脑上实测时发现：装上 1.26.17 之后，题库页一直报 500，题库打不开。
查下来是 **C 盘满了（0 KB 可用）**，而占地方的正是自动备份写出来的一个
**63 GB** 的备份包。

原因：`export_bundle` 打包时会把数据目录里的文件都收进去，但排除名单里**没有
`backups` 这个目录** —— 于是新打的备份包把上一次打的备份包也装了进去，
下一次再打就更大，这么滚下去：

```
第 1 次   约 500 MB
第 2 次   约 1 GB
第 3 次   约 2 GB
…         越滚越大 → 63 GB → 磁盘塞满 → 题库打不开
```

盘满了以后，题库的数据库连读都读不出来（`database or disk is full`），
题库页、审核页全部 500。

**这 20 来分钟里老师的题库是打不开的。** 备份包删掉、磁盘释放之后立刻恢复：
8 套卷子一个没少、题目一道没少。

## 二、修了什么

**① 备份包绝不再包含备份包**（`SKIP_DIRECTORIES` 加上 `backups` 和 `imports`）
—— 备份包是"题库的快照"，不是"备份目录的快照"。

**② 磁盘不够就不备份**（新增 `run_auto_backup` 的空间检查）
—— 打一份备份要整库的大小（还要加上压缩时的临时副本），盘不够就直接跳过并
说明原因，绝不硬塞：

```
磁盘只剩 812 MB 可用，打一份备份要 1024 MB。先腾点空间，或者把旧的备份包删掉。
```

**③ 旧备份先腾地方再打新的** —— 空间紧张时先清理超过保留份数的旧包。

**④ 失败日志不刷屏** —— 磁盘一直不够时，五分钟一次不再重复刷同样的日志。

## 三、怎么验的

- 新增三条后端断言：**备份包里不能有别的备份包**（这条直接对着这次的毛病）、
  **磁盘满时备份必须被拒绝**、**预留空间至少按 2 GB 算**；
- 后端 2310 条、前端 134 条、shell 107 条全过；
- 真机验过：把 63 GB 的坏备份包删掉，题库页立刻恢复 200、8 套卷子完好；
  那个坏包删掉后 C 盘从 0 KB 可用恢复到 63 GB 可用。

## 四、给老师的话

- **1.26.17 和 1.26.18 都有这个毛病** —— 如果另一台电脑还没升级，先别升，
  升到 **1.26.19**（这一版）就没这个问题了。
- 这一版装好之后，**每周自动备份**会正常打一份（老师的题库约 500 MB），
  留最近 10 份，磁盘不够时会自己停下来并说明原因。
- 这次的 500 是磁盘满造成的，**题库没有损坏**：8 套卷子、829 道题、302 个标签
  一个没少，坏掉的只是那一个 63 GB 的备份包（已经删掉）。
