# 题有据 1.25.1：有待办，题库页却一个提示都不给

题库里明明有几百道题等着打标签，筛选栏上一个提示都看不见。

## 问题出在哪

筛选栏上有两个入口：「AI 建议待核对」和「未标知识点」，上面的数字就是等着你处理的题数。之前它们被收在「更多筛选」里面。

问题在于，「更多筛选」这个折叠板在没有筛选内容的时候会把整个自己藏起来。两个入口跟着一起消失了 —— 于是数字看不见、按钮点不到，只能自己一家一家点进题目里翻有没有漏标的。

这是一次搬迁留下的口子：2026-10-12 撤掉左栏、给题面腾宽度的时候，待办入口被顺手挪进了「更多筛选」浮层，但没跟着挪它「什么时候该出现」。测试也一直没发现，因为验收脚本里写的是「展开折叠板之后断言它可见」—— 对着关着的折叠板断言可见，永远不会通过，所以只能先把折叠板点开，那条断言反而把错误行为当成了正确。

## 改了什么

- 这两个入口现在常驻在筛选栏上，和来源、题型、排序并排。没有待办的时候不占位置。
- 手机上第一行放不下，会自动换到下一行，不会把筛选栏撑破、整页横向滚动。
- 「更多筛选」本身没变：仍要点开才展开，展开是浮层，不推动题卡。
- 去掉了原先那个「快速查看」小标题。筛选栏里来源、题型、排序都没有小标题，按钮名本身就说是做什么的；无障碍分组名仍然保留，读屏用户听得到。

## 怎么验证的

- 新增五条变异验证：把实现分别改坏（挪回浮层、隐藏判断把它算回去、不给它留格子、没活时也不消失、按钮不渲染），要求对应测试必须失败。五条全部如期失败，且每条都从干净的实现重新开始测 —— 少了这一步，后面的变异会在前面的坏状态上测，看上去全挡住，其实一条都没验证到。
- 浏览器验收新增一条直接复现原故障的用例：把「更多筛选」藏起来，待办入口必须照样可见。
- 顺带修掉两个「假绿灯」：一是筛选栏排版断言原本只查排版里有没有提到那个位置名，把真正把元素放进格子的那行删掉它照样过；二是前端用例的运行方式会因为发现规则不匹配而跑 0 个然后报告「全过」。
